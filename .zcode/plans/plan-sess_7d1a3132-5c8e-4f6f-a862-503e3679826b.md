# VinePalma Player 全面完善计划

## Context

项目是 Tauri 2 + Rust 的跨平台本地播放器（原 Linux 为主，现需在 Windows 上可用），用户要求"尽可能完善"。经全量代码审查（前端 ~2100 行、后端 ~1250 行、脚本/CI/文档）确认的问题分四块：

1. **播放功能缺口**：播放列表/播放模式/播放进度均不持久化（store_get/set 后端已就绪但未用）、窗口几何不记忆（README 却声称记住大小）、无 MediaSession、无拖放导入、无倍速、无字幕、快捷键少、有死代码。
2. **后端健壮性**：Windows 上 `safe_link`（media.rs:321）会**整文件复制**媒体文件仅用于 probe（4GB 视频复制一份）；`run_sidecar`（media.rs:211）无超时，坏文件可让 ffmpeg 永久挂起；解码无并发去重；回环 HTTP 服务无访问凭证（本地任意进程可读取任意文件）；日志每次启动清空。
3. **构建/跨平台不一致**：package.json 用 gnu target 而 CI/README 用 MSVC；ffmpeg 构建脚本硬编码 `/tmp/opencode` 个人路径与失效 zlib 依赖、Windows 脚本实际只能在 Linux 跑但 README 教人在 MSYS2 跑；CI 无 ffmpeg sidecar（Windows/Linux 打包必失败）、签名 env 是 Tauri v1 旧名、无缓存、Linux aarch64 必失败；无 macOS sidecar 配置；版本号四处三个值（0.1.0/0.2.0/自称 0.2.1）。
4. **工程化缺失**：无 CHANGELOG、无 release 流程、无 lint/test 门禁、无 dependabot、THIRD_PARTY_NOTICES 漏 dav1d/zlib/WebView2。

用户确认：四块全做；新功能做托盘常驻、单实例锁、倍速播放、字幕支持；由我先安装本机工具链用于验证。

## 阶段 0：本机工具链准备（无代码改动）

1. 安装 VS Build Tools（C++ x64 工作负载）→ Rustup（stable-x86_64-pc-windows-msvc）→ Node.js LTS（winget 或官方安装包）→ `npm i -g @tauri-apps/cli@^2`（预编译，避免 cargo install 编译等待）。
2. ffmpeg sidecar：脚本只能在 Linux 交叉编译，本机改用**预编译静态构建**（BtbN/FFmpeg-Builds win64-gpl 的 ffmpeg.exe/ffprobe.exe）重命名为 `ffmpeg-x86_64-pc-windows-gnu.exe` / `ffprobe-x86_64-pc-windows-gnu.exe` 放入 `src-tauri/binaries/`（与 tauri.windows.conf.json 资源映射一致），供 GUI 实测。
3. 验证基线：`cargo check` + `cargo test` + `cargo tauri dev` 跑通现状。

## 阶段 1：后端健壮性（src-tauri/src/）

- **safe_link 修复**（media.rs:304）：Windows 分支直接返回 `src` 原路径（函数注释已说明 Windows 文件名是 UTF-16、无此问题），消除 probe/decode/remux 前的整文件复制。Unix symlink 逻辑不变。
- **run_sidecar 超时**（media.rs:211）：改为 `spawn()` + `try_wait` 轮询，超时 `kill()`。超时按调用点配置：probe 30s、cover 60s、decode 900s、remux 3600s。Windows `CREATE_NO_WINDOW` 逻辑保留。
- **解码/重封装去重**（server.rs:70/85）：`StreamState` 增加全局 `Mutex<()>` 解码闸门，进入后 double-check 缓存 map，防止快速切歌同一文件重复解码、不同文件并发解码打满 CPU。
- **回环服务访问 token**（server.rs）：启动时用 `RandomState` 生成 128bit 随机 hex token，`play_url/video_url/cover_url` 及新增 subtitle URL 统一带 `t=` 参数；`handle()` 校验，不匹配返回 404。前端无需改动（URL 全由 Rust 拼）。
- **缓存清理补子目录**（lib.rs:29）：`clean_cache` 遍历 `cache_dir` 根 + 一层子目录（`src/`）。
- **日志轮转**（log.rs:16）：init 时旧 `player.log` 改名为 `player.log.1`（保留一代），不再直接删除。
- 小项：`open_file` 对话框标题"选择音乐文件"→"选择媒体文件"（lib.rs:98）。
- 验证：`cargo test`（server.rs 现有 7 个测试）+ 为 parse_range/safe_link/超时补必要单测。

## 阶段 2：播放功能增强（src/index.js、index.html、mini、lib.rs）

- **播放列表+状态持久化**：单一 key `playlistState`（items 数组含 path/name/title/artist/duration/has_video + currentIndex + playMode + 播放位置秒数），`store_set` 防抖 500ms 写入；导入/删除/清空/切歌/timeupdate 时更新。启动恢复：填充列表与 UI（不自动播放），上次曲目选中；用户点播放时若有记忆位置先 seek。
- **窗口几何记忆**：JS 用 `mainWindow.onMoved/onResized`（防抖）存 `windowGeometry`{x,y,width,height,maximized}（物理像素）；Rust `setup()` 读取并 `set_position/set_size` 应用。
- **MediaSession**：`navigator.mediaSession` metadata + play/pause/previoustrack/nexttrack/seekbackward/seekforward/seekto handler，timeupdate 里 `setPositionState`。WebView2/WebKitGTK 均支持。
- **拖放导入**：前端 `onDragDropEvent` 的 `drop` 路径数组 → 新 Rust 命令 `scan_paths(paths: Vec<String>) -> Vec<TrackInfo>`（目录走现有 `scan_media_files`+`probe_all`，文件逐一 probe），注册进 `generate_handler`。
- **倍速播放**：底部控制区加"1.0x"按钮循环 1.0→1.25→1.5→2.0→0.75；作用于 activeMedia 并在切歌后恢复，存 key `playbackRate`。
- **快捷键扩展**（index.js:1295）：↑/↓ 音量±5、M 静音、N/P 切歌、F 窗口全屏、L 播放模式、0-9 跳百分比（Space/←→/Esc 已有）。
- **播放列表搜索框**：playlist-header 加输入框，按 title/artist 实时过滤。
- **死代码清理**：index.html:84-85 隐藏 play/pause 按钮及对应 JS、index.js:1207-1234 注释掉的 durationchange 块、`fixedDuration` 残留注释。
- **设置页新增**："关闭时最小化到托盘"开关（key `closeToTray`，默认开），供阶段 4 使用。
- 验证：`cargo tauri dev` 手动 GUI 清单（导入→播放→重启恢复、拖放、倍速、快捷键、MediaSession 系统面板）。

## 阶段 3：字幕支持

- **Rust**（media.rs/server.rs/lib.rs）：
  - `list_subtitles(path)`：ffprobe `-show_streams` 过滤 `codec_type=subtitle` 且解码器可转文本（subrip/ass/mov_text/webvtt，跳过 pgs 位图），返回 {index, codec, language, title}。
  - `subtitle_url(path, stream_index)`：ffmpeg `-map 0:s:<n> -f webvtt` 提取转 VTT，缓存 `<short_key>-sub<n>.vtt`，走 `/subtitle?p=&t=` 端点（Content-Type text/vtt，token 校验）。
- **前端**：视频浮层加"CC"按钮循环 关闭→轨道1→…；`<video>` 动态挂 `<track kind="subtitles" srclang>`，切轨用 textTracks mode；音频曲目禁用。字幕状态随 emitMiniState 可忽略（迷你卡不加）。
- **ffmpeg 脚本**：两个脚本的 configure 增加 `--enable-muxer=webvtt`、`--enable-decoder=srt,ass,movtext,webvtt`（当前缺失，不加则提取必失败）。
- 验证：用带 SRT/ASS 轨的 MKV 实测轨道列表、切换、渲染。

## 阶段 4：托盘常驻 + 单实例

- Cargo.toml：tauri features 加 `"tray-icon"`；新增 `tauri-plugin-single-instance = "2"`。
- lib.rs `run()`：注册 single-instance（二次启动时唤起并 focus 主窗口）；构建托盘（图标用现有 `icons/32x32.png`，菜单：显示主窗口 / 迷你播放器 / 退出）。
- 关闭行为：`on_window_event` 拦截 main 窗口 `CloseRequested`，读取 store `closeToTray`（默认 true）→ 为 true 时 `prevent_close()` + `hide()`（迷你/设置窗口不受影响），托盘"退出"才真正退出并销毁托盘。
- 验证：Windows 托盘图标、关闭隐藏、托盘退出、二次启动唤起。

## 阶段 5：构建与跨平台一致性

- **工具链统一 MSVC**：package.json `build:windows` 改 `--target x86_64-pc-windows-msvc`，新增 `build:macos`/`build:ffmpeg:macos`。ffmpeg 二进制是独立进程，mingw 交叉编译的 sidecar 在 MSVC 应用中运行无碍，**保留 `-x86_64-pc-windows-gnu` 产物命名**并在文档说明，不迁移 externalBin（低风险）。
- **ffmpeg 脚本修正**（两脚本）：`BUILD_DIR` 默认 `${TMPDIR:-/tmp}/vinepalma-ffmpeg-build`；源码改官方 ffmpeg.org/releases 为主源、Debian pool 为回退；**Windows 脚本自建 zlib**（mingw 交叉编译静态 libz，失败则 `--disable-zlib`），删除 `/tmp/opencode` 硬编码；env 开关统一 `ENABLE_X264`/`ENABLE_DAV1D`（兼容旧 `FFMPEG_NO_*`）；Linux dav1d 分支不再强制 `--enable-gpl`（dav1d 是 BSD，仅 x264 需要 GPL）；加字幕相关 enable（阶段 3）。
- **新增 scripts/build-ffmpeg-macos.sh**：本机编译 arm64（uname -m 映射 triple），精简配置（macOS WKWebView 原生解 H264/HEVC，无需 x264/dav1d），产出 `ffmpeg-aarch64-apple-darwin`。
- **新建 tauri.macos.conf.json**：targets ["app","dmg"] + ffmpeg/ffprobe 资源映射；tauri.windows.conf.json 加 `targets:["nsis"]` + nsis.languages(SimpChinese/English)；tauri.linux.conf.json 加 `targets:["deb","appimage"]` + `deb.depends:["libwebkit2gtk-4.1-0","libgtk-3-0"]`；主 conf longDescription 补英文。
- **版本统一 0.3.0**：package.json、package-lock.json、src-tauri/Cargo.toml、tauri.conf.json、README 状态行。
- **CI 重写 build-tauri.yml**：ffmpeg sidecar 改为 CI 内**下载预编译**（BtbN win64/linux64、evermeet.cx macOS）+ `actions/cache` 按版本缓存 `src-tauri/binaries/`；移除 Linux aarch64 与 macOS x86_64 matrix（注释注明原因）；删除无效的 Tauri v1 签名 env 与死 env VERSION；tauri-cli 改 npm 全局安装 + 加 Swatinem/rust-cache；删空转的 npm install；Windows 显式 `--bundles nsis`；触发加 tag `v*` + release job（softprops/action-gh-release 上传安装包）。
- **CI 新增 lint/test job**：`cargo fmt --check` + `cargo clippy --all-targets -- -D warnings` + `cargo test`（本阶段先把存量 fmt/clippy 警告修干净）。
- .gitignore 补 `.env`。
- 验证：本机 `cargo tauri build --bundles nsis` 产出安装包并安装实测；CI 推送后观察全绿。

## 风险与备注

- VS Build Tools 下载量大（~2GB），若安装失败回退方案：改用 gnu 工具链（rustup + MSYS2 mingw-w64）
- 托盘在 Linux 需 libappindicator（CI 已装）；README 补充说明
- 拖放在透明窗口 + WebView2 上如有异常，回退为仅 playlist-panel 支持拖放
- 前端还有 1 个探索代理在后台运行，其报告到达后仅用于补充遗漏项，不影响本计划主体
